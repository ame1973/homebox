# HomeBox web client

This is the same-origin React/TypeScript application served by the Go executable. It provides real server liveness, administrator setup/login/forced-password-change/logout, responsive location hierarchy/detail/editor/move/archive/restore/delete, reviewed category/tag settings, and catalog metadata list/detail/create/edit/archive/restore/delete plus owned barcode/alias/attribute/Tag maintenance and reviewed physical Unit/Stock workflows. It does not simulate inventory or expose unimplemented contents/photo/history/QR actions. The service worker, offline replica, persistent drafts, camera, privileged reauthentication consumers, and remaining domain flows are still being built.

## Install and run

Use Linux/WSL2, Node 24.14.1 (see `../.node-version`), npm 11.14.1, and the Go version in `../server/go.mod`. From the repository root:

```sh
make setup-web build-web build
./bin/homebox db migrate --database ./data/homebox.sqlite
./bin/homebox serve --database ./data/homebox.sqlite --web-dir ./web/dist
```

Open exactly the printed `public_origin` (normally `http://127.0.0.1:8080`). Keep this incomplete build on loopback. Authentication, account/location/taxonomy pages, seven location metadata HTTP operations, eight category/tag HTTP operations, six catalog HTTP operations, fourteen owned catalog operations, their reviewed screens/typed adapters, and direct TLS/explicit proxy features are implemented. Catalog metadata and responsive foreground Unit/Stock screens, all twelve HTTP operations and stateless typed adapters are available; media/assisted creation, asset/history domains and production deployment remain pending. See [HTTP Authentication and Transport](../docs/http-authentication.md) and [Location Rules and Usage](../docs/locations.md). `serve` requires a migrated database and a nonempty frontend build and does not silently migrate data. Stop it with Ctrl+C.

For hot reload, the Go origin must match the browser's Vite origin, and Vite must preserve that Host while forwarding `/api`:

```sh
# Terminal 1: migrated private database and built frontend already exist.
./bin/homebox serve --database ./data/homebox.sqlite --web-dir ./web/dist \
  --public-origin http://127.0.0.1:5173

# Terminal 2: open exactly http://127.0.0.1:5173, not localhost or a LAN address.
npm --prefix web run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

The default Vite proxy targets `http://127.0.0.1:8080`; it does not change Host or enable proxy-header trust. Do not reuse an unrelated service if either port is occupied. For another local port pair, update the Vite proxy target and Go public origin together. The adapters are covered by unit/runtime-contract tests and the built account/location pages by isolated real-server browser tests; an earlier development-module smoke also used separate Vite/Go ports. The production runtime needs only the Go executable and `web/dist`, not Node.js, npm, or Python. Linux amd64/arm64 binaries are built with `make build-linux`; hardware execution is a separate acceptance gate.

## Source and state boundaries

- `components/ui` comes from the official shadcn CLI 4.23.0, Radix base, Nova preset. Its upstream MIT notice is retained. Compose these primitives in feature components; do not create another base-control framework. Theme menu targets are 48 px; primary controls are at least 44 px.
- Tailwind semantic tokens provide paired light/dark colors and local system/CJK fonts. There are no hosted fonts, CDN assets, analytics, or third-party requests in the application.
- React Router's data router owns routes and the real dirty-navigation blocker. TanStack Query owns temporary server-read state; Zustand stores only the theme preference. Neither is an authoritative inventory store. Account mutations use nonserializable short-lived work closures with immediate cache GC/reset; session transitions cancel/purge query and mutation state.
- Account forms use React Hook Form/Zod and official Field/Input/AlertDialog composition. Secrets clear on background/unmount/completion; uncertain sent writes are reconciled through fresh reads/login, never silently replayed. A failed lazy chunk has explicit recovery. Theme pairs switch atomically and menus are viewport-bounded at larger text sizes.
- The shared generated OpenAPI client uses same-origin credentials/no-store and rejects redirects. Reads have an eight-second deadline; auth writes have 30 seconds. Pre-canceled requests are not sent, late canceled results are discarded, and all timers/listeners are cleaned up. Cancel/timeout after a write was sent does not prove the server rolled it back: treat the result as uncertain and reconcile explicitly, never silently replay it.
- The seven auth adapters validate success payloads with strict Zod schemas. They accept CSRF/idempotency/signal explicitly, send the package's application version, never read cookies or retain tokens in storage, and never secretly refresh/retry/replay a write. CSRF/grants remain the caller's memory-only responsibility. Errors retain only allowlisted codes, status, bounded Retry-After, and safe request IDs, not arbitrary server messages/details/transport causes. `validAuthText` counts Unicode code points and rejects lone surrogates without trimming/normalizing credentials.
- Location adapters cover explicit page/detail/create/patch/move/archive/delete calls with strict Unicode/safe-integer/identity/ETag/revision checks, root-versus-child creation proofs, caller-owned CSRF/key/signal, eight-second reads and 30-second writes, no hidden refresh/rebase/retry/persistence, and shared safe error normalization.
- Category/tag adapters expose the eight contracted operations with separate root/child category proofs, exact-name/partial-null validation, bounded explicit pages, stable resource identity/strong ETag/acknowledgement checks, caller-owned CSRF/key/signal, and no implicit retry/rebase/refresh/storage. Common domain validation and proof/response primitives are shared with locations; `tree` is reserved only for the location read route. Taxonomy settings screens use those adapters for complete live lists, explicit creation/edit/deletion reviews, manual changed-field adoption and original-key reconciliation even after a target disappears. See [Categories and Tags](../docs/taxonomy.md).
- Catalog adapters expose six real operations with exact nullable metadata, nonempty partial edits, compile-time/runtime complete custom measurement tuples, no outgoing server-default insertion, civil-date/query/page checks, and original identity/ETag/revision/deletion acknowledgements. Required nullable continuations and direct-filter consistency are validated; there is no automatic pagination or write replay. Real browser tests bundle the actual SDK only into private temporary web roots and serve it through the Go origin, covering historical replies and genuinely committed malformed-response reconciliation. Catalog metadata screens use the verified adapter without exposing that test entrypoint. See [Catalog Item Rules](../docs/catalog.md).
- Owned catalog adapters expose all fourteen barcode/alias/attribute/tag operations with original Item-versus-row proof contexts, retained owner checks, strict exact-text/partial-attribute/ordered-tag inputs, legacy-safe resource responses, required full live pages and matching resource/acknowledgement revisions. Eight-second reads/thirty-second writes use the same caller-owned CSRF/key/signal and safe transport, with no storage, refresh, rebase or replay. Strict compile fixtures enforce complete creation/nonempty patches and owner-bearing row contexts. Private actual-SDK/Go browser tests cover signed scopes, frozen replies and explicit original-key reconciliation after a genuine wrong-owner response; no test entry enters production. Reviewed maintenance screens use those same adapters. See [Catalog Links and Tag Membership](../docs/catalog-links.md).
- Holding adapters expose all twelve real Unit/Stock operations using shared transport/domain/catalog validation. Unit creation uses the original Item proof; later Unit commands retain original Unit proof/owner. Stock writes require one whole reviewed Item snapshot, bind its revision/measurement and validate independent affected-balance ETags, not Item-plus-one. Exact `item_id` Stock reads validate every returned owner and signed scope without scanning/filtering an unrelated browser page; absence preserves prior unfiltered cursor MACs. Strict nullable/nonempty/discriminated inputs, required distinct live pages, Stock-only 4 KiB continuations, eight-second reads and thirty-second writes add no hidden defaults, pagination, refresh, rebase, storage, retry or reconnect submission. Runtime/strict compile tests and private actual-SDK/Go browser tests cover all operations, zero/no-op states, signed scopes, frozen replies and identical original-key reconciliation after genuinely committed wrong-owner/wrong-measurement/lost replies. Foreground holding screens use these adapters and reviewed state below. See [Individual Units and Quantity Stock](../docs/holdings.md).
- Holding state completes only the actual Item-scoped collection between matching Item reads and brackets independent Unit/owner reads without loading siblings. Exact nullable Unit/changed-only forms, explicit physical kinds and the shared canonical count parser preserve drafts without conversion. Volatile commands freeze original Item/Unit/balance/path context; safe leg previews distinguish missing versus retained zero and active placement versus archived outflow. The shared no-replay controller invalidates holding/catalog/location reads only, never installing historical replies; catalog/owned/taxonomy/location changes invalidate their dependent holding scopes in return. Runtime and private actual-Go browser cases drive all writers and original-key historical reconciliation. The responsive route composition now uses this tested state for complete lists, exact Unit/Stock editors and explicit reviews, not a persistent draft queue. Changed source/path/measurement requires deliberate adoption; new offline editors wait for current authority, initialized offline drafts never auto-submit, and session loss retains only validated route/filter/cursor context through login. All viewports share the same capabilities with dirty/Back/Escape/focus protection and enlarged light/dark checks.
- Owned maintenance state completes the selected signed collection under its own discriminated collection/Item cache scope; only Tag editing also reads the complete available index. Before/after Item checks reject mixed revisions/labels, and larger legacy membership stays complete without inventing empty unqueried sets or repeatedly loading unrelated private collections. A newly mounted editor waits for its first current read before initializing from cache; later refetches retain volatile drafts. Form helpers reuse SDK validation, changed-only bodies and explicit barcode-pair/member-delta adoption without fixing invalid drafts or truncating sets. Commands freeze original owner/row/label/body context and use the same no-replay controller/read-only invalidation. Actual responsive row/Tag screens retain source/deletion context, selected-label rechecks, stable validation geometry and exact scoped-list returns; there is no persistent draft queue or pretend camera.
- Catalog metadata state reuses SDK validation, preserves null versus supplied-empty brand/model, parses the original safe positive integer scale, emits changed-only patches and keeps measurement interpretation together during explicit adoption. Volatile commands preserve selected category labels and original item proofs; the shared foreground controller invalidates catalog/taxonomy and dependent holding read scopes on confirmation or sent failure, never installing historical replies. The responsive metadata screens use those tested form/command helpers, explicit dialogs and leave guards. They retain unavailable category selections, require manual rechecking/adoption after changes, preserve filter/cursor context across normal detail/edit returns, and explain the still-pending purchase/photo/camera/bulk/import capabilities. Localized error space stays stable during blur validation so a pointer target cannot move between down/up.
- Location screens publish only complete validated graph reads, use iterative paths/traversal, preserve original parent/subject proofs, and submit changed metadata only. Every mutation has visible review and a frozen volatile proposal. Unknown sent outcomes retain the original key/body/proof for explicit retry and read-only reconciliation; historical replies never overwrite authoritative query data. Conflicts require an explicit draft/current comparison, not automatic rebase. Parent selection is native; no second control framework or rendering dependency is added. Inputs remain volatile, with dirty/back/reload warnings and no claimed offline replica.
- Dialog composition permits a shrinkable grid at larger text sizes without editing generated primitives. Reviews initially focus visible static content rather than an offscreen footer; read-dependent controls do not animate through low-contrast enabled opacity. Long paths/names wrap instead of widening the page.
- Shared foreground mutation composition preserves synchronous first-Escape handling, visible static review focus, original request/proof retention, no historical cache overwrite and dirty/Back/reload guards across location/taxonomy forms. Long review fields use the already keyboard-accessible outer dialog scroller, not unfocusable nested read-only scroll regions. Login round-trips allow only validated implemented settings/location/catalog/holding paths and normalized catalog filters/cursors, never arbitrary redirects, raw draft bodies or amounts.
- Queries can recheck after reconnect. Mutations explicitly use `networkMode: always` and no retry so an offline write cannot be paused and silently replayed. This is tested. All writes still require explicit confirmation and authoritative server validation.
- Generated `src/lib/api/schema.d.ts` is committed and checked for drift. Generation/checking uses `--default-non-nullable=false`: a server default must not make an optional request field mandatory in TypeScript. Minimal location/item creation and nullable parent commands have strict compile fixtures with `skipLibCheck: false`. JSON Schema constraints such as integer bounds and conditional OCR visibility still require runtime validation; TypeScript alone cannot enforce them.
- UI strings use stable keys in `src/lib/messages.ts`; the default language is Traditional Chinese. Canonical documentation remains English.

## Dependency audit status

The lockfile is exact and installation disables lifecycle scripts. As of 2026-11-05, `npm audit --omit=dev` reports zero vulnerabilities. The full audit reports two low and four moderate findings in development tooling chains: deepmerge via shadcn/registry ([GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)), and minimatch via ts-morph ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)). These are current registry classifications, not a claim that the form-tool installation fixed earlier advisories. They are not application-runtime dependencies, but remain unresolved development-tool exposure.

Use the generators only with trusted local contracts and the official shadcn registry, not untrusted downloaded configuration. CI fails on any runtime advisory and on high/critical full-tree advisories; lower developer-tool findings remain visible. Do not use `npm audit fix --force` or incompatible global overrides: the suggested downgrades change supported APIs, and Redocly's callable minimatch API is not compatible with minimatch 11's named-export API. Recheck upstream compatible fixes before release.
